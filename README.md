# Persona Manager

SillyTavern 페르소나 설명문을 **항목별로 나눠 쓰고**, 조합을 **버전**으로 저장해 한 번에 바꾸는 확장입니다.
페르소나마다 **이미지 폴더**를 두고 채팅에 그림을 넣을 수도 있습니다.

> **English.** A SillyTavern extension that splits a persona description into named items
> with selectable choices, saves combinations as versions, keeps an edit history, and gives
> each persona an image folder whose pictures render in chat via `{{pimg::name}}`.
> Korean UI. No build step and no runtime dependencies.

## 할 수 있는 일

- 입력창 옆 아이콘 하나로 페르소나와 버전 전환
- 설명문을 외모, 성격, 말투 같은 **항목**으로 나누고, 항목마다 여러 **선택지** 중 하나를 고르기
- 지금 조합을 **버전**으로 저장. 버전마다 페르소나 이미지와 위치·크기도 지정
- 고칠 때마다 이전 본문을 **이력**으로 보관하고, 차이를 보며 되돌리기
- 페르소나 **이미지 교체** 시 바로 위치·크기를 맞추고, 모든 화면에 즉시 반영
- 대화 언어에 맞춰 페르소나 이름 자동 변경 (한국어 / 일본어 / 중국어 / 영어)
- 첫 메시지(그리팅)를 스와이프해도 `{{user}}` 자리에 지금 페르소나 이름이 나오도록 유지

## 설치

1. SillyTavern **확장 → 확장 설치**에 `https://github.com/Penterson/st-persona-manager` 를 넣습니다.
   또는 이 폴더를 `SillyTavern/public/scripts/extensions/third-party/st-persona-manager/` 에 복사합니다.
2. 확장 목록에서 **Persona Manager**를 켭니다.
3. 입력창 왼쪽에 페르소나 아이콘이 보이면 준비 끝입니다.

필요한 브라우저: Chromium 111+, Safari 16.4+, Firefox 121+ (최근 Android 브라우저는 모두 해당).

## 처음 3분

1. 입력창 옆 **아이콘**을 누르면 빠른 패널이 열립니다.
2. **버전 ▸ 현재 페르소나 관리 시작**을 누릅니다.
   - 설명문에 `## 외모`, `[성격]`, `말투:` 같은 제목 줄이 있으면 그 제목에 맞는 항목으로 나뉩니다.
     이때 제목 줄은 고른 제목 형식(`## 이름` 또는 `이름:`)으로 통일됩니다.
   - 제목이 없거나 설정에서 분류를 끄면 설명문이 한 글자도 바뀌지 않고 첫 항목에 들어갑니다.
3. 패널 아래 **편집**으로 관리자 화면을 엽니다. 항목을 열어 본문을 고치고 저장하면
   SillyTavern 설명문이 바로 바뀝니다.
4. 마음에 드는 조합이 되면 **버전 탭 ▸ 현재 구성을 버전으로 저장**. 이후 빠른 패널에서
   버전 이름을 한 번 누르면 조합이 통째로 바뀝니다.

## 화면 안내

### 빠른 패널 (입력창 아이콘)

| 구역 | 하는 일 |
| --- | --- |
| 현재 | 플레이 중인 페르소나와 적용된 버전. 조합이 버전과 다르면 `(수정 있음)` |
| 버전 | 누르면 적용. `⋯`로 이름 변경, 덮어쓰기, 복제, 순서, 삭제 |
| 언어별 이름 | 언어마다 등록한 이름을 바로 적용. 자동 적용 스위치 |
| 페르소나 | 목록 / 타일 보기, 정렬, 검색(초성·오타 허용), 그룹 칩 |
| 아래 단추 | 관리자 화면의 각 탭으로 바로 이동 |

### 관리자 화면

| 탭 | 하는 일 |
| --- | --- |
| 편집 | 항목과 선택지 편집, 전문 보기, 제목별 분류, 기본 항목 채우기, 제목 형식, 태그, 페르소나 이름·이미지·복제, 언어별 이름, 프롬프트 배치 |
| 버전 | 버전 저장·적용. 버전마다 태그, 사용할 그림, 적용 시 바뀔 페르소나 이미지와 위치·크기 |
| 이력 | 선택지별 지난 본문. 이전 / 지금 / 차이 보기, 되돌리기, 변경 기록 |
| 에셋 | 이 페르소나의 그림 폴더. 올리기, 삭제, 채팅에 넣기 |
| 그룹 | 그룹 만들기·이름 변경·삭제, 페르소나 넣고 빼기 |

상단 페르소나 이름을 누르면 다른 페르소나로 이동합니다. 플레이 중이 아닌 페르소나도 편집할 수 있습니다.

### 설정 서랍

**표시 / 페르소나 목록 / 이력 보관 / 설명문 / 에셋 매크로 / 진단과 데이터** 여섯 구역입니다.

## 핵심 개념

| 말 | 뜻 |
| --- | --- |
| 항목 | 설명문의 한 조각(외모, 성격 …). 순서가 곧 프롬프트 순서 |
| 선택지 | 한 항목이 가질 수 있는 여러 본문. 항목마다 하나만 활성. 빈 본문은 제목째 빠짐 |
| 버전 | "항목마다 어떤 선택지"의 조합. 본문을 복사하지 않고 가리키기만 하므로, 본문을 고치면 그 선택지를 쓰는 모든 버전에 반영 |
| 이력 | 본문을 저장할 때마다 이전 본문 보관 |
| 에셋 | 페르소나별 그림 폴더(SillyTavern sprites 저장소의 `persona_<아바타 파일명>`) |

## 이미지

- **페르소나 이미지 교체** — 편집 탭 ▸ 페르소나 ▸ 이미지 **교체**. 파일을 고르면 위치·크기 조절 창이 열립니다.
  끌어서 위치, 두 손가락·휠·막대로 확대한 뒤 **이 위치로 적용**, 또는 **자르지 않고 그대로**.
  입력창 아이콘, 패널, 관리자, SillyTavern 페르소나 목록과 채팅 아바타가 새로고침 없이 바로 바뀝니다.
- **버전별 이미지** — 버전 탭에서 버전을 열고 **이미지 지정**. 에셋 탭을 먼저 열 필요는 없습니다.
  **위치·크기**로 틀을 맞추면 그 버전을 적용할 때 잘린 그림이 들어갑니다.
- **원본 되돌리기** — 버전 이미지를 처음 적용할 때 원래 이미지를 `pm-backup-…` 이름으로 보관합니다.
- **채팅에 그림 넣기** — 본문에 `{{pimg::이름}}`. 이름은 파일 이름에서 확장자를 뺀 것이고 대소문자는 구분하지 않습니다.
  `{{pimg::폴더/이름}}`처럼 쓰면 다른 페르소나의 그림도 됩니다. 저장된 메시지에는 태그가 그대로 남습니다.
- **매크로** — `{{persona_assets}}`는 쓸 수 있는 그림 이름 목록, `{{persona_asset_prompt}}`는 그 목록을 넣은 안내문.
  캐릭터 카드나 시스템 프롬프트에 넣어 모델에게 그림 사용법을 알려 줍니다.

## 언어별 이름 자동 적용

대화 언어를 보고 그 언어로 등록한 이름으로 페르소나 이름을 바꿉니다. 판단 근거와 비중:

| 근거 | 비중 |
| --- | --- |
| 내가 보낸 메시지 | 가장 큼 |
| 캐릭터 답장 | 큼 |
| 첫 메시지(그리팅), 캐릭터 설명·성격·시나리오 | 보통 |
| 캐릭터 이름 | 작음 |
| 내 페르소나 설명 | 가장 작음 |

그래서 새 채팅에서 그리팅이 한 줄뿐이어도 캐릭터 정보로 판단하고, 내가 다른 언어로 쓰기 시작하면 곧바로 그 언어를 따릅니다.
`{{user}}`, HTML 태그, 링크는 판단에서 뺍니다. 지금 판단 결과는 편집 탭 ▸ 언어별 이름의 **지금 대화 언어**에 나옵니다.
같은 이름의 페르소나나 같은 이름의 캐릭터가 있으면 바꾸지 않습니다.

## 그리팅의 `{{user}}`

SillyTavern은 첫 메시지를 처음 그릴 때 `{{user}}`를 그때의 이름으로 바꿔 저장합니다. 그 뒤 페르소나 이름을 바꾸거나
다른 페르소나로 바꾸면 그리팅과 스와이프 대안에 옛 이름이 남습니다. 이 확장은 **아직 답하지 않은 그리팅**에 한해,
캐릭터 카드 원문에서 `{{user}}`가 있던 자리만 지금 이름으로 고칩니다. 원문에 그냥 적힌 같은 단어는 건드리지 않습니다.
1:1 채팅에만 적용됩니다(그룹 채팅은 SillyTavern이 스스로 다시 불러옵니다).

## 바깥에서 설명문을 고쳤을 때

SillyTavern 페르소나 화면에서 설명문을 직접 고치면 패널에 **외부 수정** 알림이 뜹니다.

- **되돌리기**: 관리자 내용으로 다시 씁니다.
- **가져오기**: 바깥 내용을 본문이 든 항목(없으면 첫 항목)으로 가져옵니다.
- 그대로 두고 관리자에서 다른 것을 저장해도 바깥 내용은 사라지지 않습니다. 그 항목에 `외부 수정 MM-DD HH:mm` 선택지로 보관됩니다.

## 데이터와 백업

- 모든 데이터는 SillyTavern `settings.json`의 `extensionSettings["persona-manager"]`에 있습니다.
  설명문 자체는 SillyTavern 자리에 쓰이므로 확장을 꺼도 마지막 설명문은 남습니다.
- **설정 내보내기**로 전체를 JSON으로 받고, **설정 가져오기**로 통째로 되돌립니다. 가져오기는 현재 데이터를 모두 바꾸니 먼저 내보내 두세요.
- 이력 상한: 선택지별 개수 상한을 넘으면 가장 오래된 것부터 조용히 밀려납니다.
  총량·기간 상한으로 지워질 때는 변경 기록에 한 줄 남습니다.
- 더 새로운 판이 만든 데이터는 **읽기 전용**으로 보여 주기만 하고 저장 파일은 건드리지 않습니다.

## 문제 해결

| 화면에 보이는 말 | 뜻과 해결 |
| --- | --- |
| 이름이 같은 페르소나가 여럿이라 … 편집 잠금 | 활성 페르소나를 확정할 수 없습니다. 이름을 다르게 하세요. 전환은 잠기지 않습니다. |
| 더 새로운 판이 만든 데이터라 읽기 전용 | 확장을 최신으로 올리세요. |
| 프롬프트에서 빠지는 빈 항목 N개 | 활성 선택지의 본문이 비어 있습니다. 본문을 쓰거나 항목을 지우세요. |
| (삭제된 선택지) | 버전이 가리키던 선택지가 지워졌습니다. 버전의 `⋯`에서 다시 고르세요. |
| 에셋 목록 읽기 실패 | sprites API가 응답하지 않았습니다. 채팅을 다시 열면 다시 시도합니다. |
| `{{pimg::…}}`가 글자로 남음 | 그 이름의 그림이 폴더에 없습니다. 에셋 탭의 이름과 비교하세요. |

## 개발

```bash
npm install     # 개발용 playwright (스모크 테스트에만 필요)
npm test        # 문법 검사 + 단위 테스트 (Node 20+, 의존성 없음)
npm run smoke   # 헤드리스 Chromium으로 모든 화면 구동, 스크린샷은 test/browser/out/
```

### 구조

```
index.js               진입점: 이벤트 연결, 채팅 그림, 그리팅 {{user}} 동기화, 해제
modules/
  state.js             지금 어느 페르소나이고 그 데이터는 무엇인가 (유일한 출처)
  ctx.js               활성 페르소나 식별
  store.js             데이터 모델, 기본값, 스키마 이행
  compose.js           항목 → 설명문 조합, SillyTavern에 쓰기
  classify.js          제목 줄로 항목 분류
  history.js           이력, 상한, 되돌리기, 단어 단위 차이
  roster.js            페르소나 목록 정렬·그룹
  search-pure.js       검색, 언어 판단(대화 맥락 가중 투표), 페이지
  greeting.js          그리팅의 {{user}} 이름 동기화
  framing.js           이미지 위치·크기(자르기) 계산
  assets.js            sprites API, {{pimg::}}, 아바타 쓰기, 매크로
  manager-pure.js      관리자 화면 순수 로직
  quickbar-pure.js     빠른 패널 순수 로직
  dom.js               세 화면 공용 DOM 도우미
  quickbar.js          빠른 패널
  manager.js           관리자 화면
  settings-ui.js       설정 서랍
  strings.js           사용자가 읽는 모든 문장
style.css              SillyTavern 테마 변수로만 색을 만드는 스타일
```

`*-pure.js`, `store`, `compose`, `classify`, `history`, `roster`, `framing`, `greeting`은 DOM과 SillyTavern 없이
Node에서 그대로 테스트됩니다. 화면 모듈의 핸들러는 컨텍스트와 노드를 붙들지 않고 실행 시점에 다시 읽습니다.
